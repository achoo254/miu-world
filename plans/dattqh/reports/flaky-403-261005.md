# Intermittent server test failures (stray 403/404/503) — root cause and fix

Date: 2026-10-05 · Fix commit: `64cd9a8b` · Scope: tests only, no product code changed.

## Root cause

Requests from the server tests were sometimes answered by **another program on the Mac**, not by the app under test.

- Every server test reached the app through supertest with a bare Express app (`request.agent(app)` in `apps/server/test/test-app.ts`, plus `request(t.app)` / `request.agent(createApp(...))` in five test files).
- Given a bare app, supertest 7.3 calls `app.listen(0)`, which binds the IPv6 wildcard `[::]`, then rewrites the host to `127.0.0.1` for the URL. It also closes and re-listens the server between sequential requests, so a server run made about 2,450 such binds.
- On macOS, binding `[::]:P` **succeeds** while another process listens on `127.0.0.1:P`, and a connection to `127.0.0.1:P` goes to that more specific socket. The other program then answers with its own status and a non-JSON body.
- On this Mac, Orca already listens on `127.0.0.1:49209`. Other projects' dev servers add more such ports. Ports are handed out sequentially, so a run fails whenever the counter passes one of those ports. A fuller suite makes more binds, which explains why the failures appeared "under full-suite load". Linux CI refuses that bind (`EADDRINUSE`), which is why CI never showed it.

## Evidence

| Check | Result |
|---|---|
| Plain Node: `listen(49209)` while Orca holds `127.0.0.1:49209` | Bound `::` 49209; `GET 127.0.0.1:49209/api/x` answered **404 by Orca** |
| Same with a fake program on `127.0.0.1:P` answering 403 | Wildcard bind OK, request answered **403 by the other program**; explicit `127.0.0.1:P` bind → `EADDRINUSE`; `127.0.0.1` bind over a foreign wildcard → ours answers |
| Unmodified server suite, first run in this session | 1 failure: seeded-run test got **403** mid-test |
| Server suite with 371 fake programs (403/404/503) on every 20th port ahead of the port counter, before fix | 105 colliding binds → **101 failed tests**: `expected 200 "OK", got 403 "Forbidden"` (13), `got 503` (12), `got 404` (12), and others. The response bodies were `{}` (non-JSON; this app always answers `{ error }`). A temporary log on the `consent-required` path never fired |
| Same, after fix, 1,498 fake programs on every other port across the exact range used | **0 collisions, 530/530 passed**; binds dropped from 2,451 to 41 (one per test app) |

## Hypotheses eliminated

The 403s were never produced by the app itself: the temporary server-side logs showed no `consent-required`, `forbidden-origin` or `server-busy` on the failing calls, and the bodies were not JSON. The following causes were therefore ruled out:

- rate limiters (they answer 429);
- the hash queue (it answers 503 with `server-busy`);
- consent visibility or transactions;
- the clock offset (`advance` is not used in `quest-routes.test.ts`);
- module-level caches;
- test order.

Five reruns without fake programs passed, which is consistent with a rare collision that depends on the port counter.

## Fix

- `listenOnLoopback(app)` in `apps/server/test/test-app.ts` listens on `127.0.0.1` itself, so the kernel refuses a port that is already held. `TestApp` gains:
  - `server`;
  - `request()`, a one-off request with no cookies and no Origin;
  - `agentFor(otherApp)`, for apps sharing the same database.

  `handle.close()` also closes these servers.
- The five test files and `app.test.ts` now use these helpers. ESLint (`@typescript-eslint/no-restricted-imports`, type imports allowed) blocks value imports of `supertest` in `apps/server` outside the helper.
- Regression test `apps/server/test/test-app.test.ts`, added to the vitest `include`:
  - It holds a port on 127.0.0.1 with a fake program and expects `listenOnLoopback` to be refused with `EADDRINUSE`.
  - It checks that the test app serves on 127.0.0.1 and closes its servers with the database.
  - With the bind switched back to supertest's wildcard behaviour, both tests fail: the promise resolves instead of rejecting, and the address is `::`.
- `docs/code-standards.md` (Backend) records the rule.

## Gates

- `pnpm typecheck` and `pnpm lint` (`--max-warnings=0`): both exit 0.
- `pnpm test` run twice in a row: each time 504 files passed with 1 skipped (`zz-probe.test.ts`, already skipped before this change), 6,294 tests passed with 1 skipped, exit 0 (141.7 s and 127.1 s).
- `assets:check` and `content:check` were not run because no assets or content changed.

## Unresolved

- The earlier 503s on this machine came from whichever local program held the port at that moment; it was not identified, and the fix makes that unnecessary.
